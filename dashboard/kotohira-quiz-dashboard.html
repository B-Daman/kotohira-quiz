プロダクト概要

目的・ターゲット・出題方針（要件定義より）
🎯 目的

琴平町への興味を育て、知識を定着させるためのクイズ。検定試験ではなく、 「知らなかった → 知った → 覚えた」のサイクルを回すことが最優先。成功指標はプレイ回数を主とする。

👥 ターゲットユーザー
メインターゲット
  • 観光客（訪問の前・中・後に楽しむ）
  • 移住検討者
  • 琴平町DAOメンバー
  • 琴平ファン・リピーター
  • 着任したばかりの役場職員
サブターゲット（副産物）
  • 地元住民（hard問題で深い知識を楽しむ）
  • 上級志向のリピーター

メイン向けにしっかり設計し、上級者も自然に楽しめるようにする（hard問題が受け皿）。

📦 コンテンツのスコープ
含める
  • 金刀比羅宮とその信仰
  • 琴平町の歴史・地理・文化・産業・観光・人物
  • 町内の店舗・施設・イベント・食文化
除外する
  • 琴平と接点のない香川県全般
  • 隣接自治体単独の情報（関連言及は可）
  • 変わりやすい時事情報（料金・営業時間）
📝 出題形式と難易度

4択のみ（記述式・○×式は不採用）。正解は常に1つで明確に正しい。 「選択肢があるから、わからなくても選べる → 解説で学ぶ」体験を成立させる。

🧠 出題パターン（認知レベル）

主力（80%以上）＝事実想起・定義説明・分類・概念説明。 積極的に増やすのは因果・理由型（なぜ○○か?）＝「へぇ」感が高く知的好奇心を刺激するため、各テーマに最低1問。 最善判断・予測型は不採用。

目標: 記憶・理解70%以上／分析（理由型）5–10%／応用・評価5%以下。

出題モード（Webアプリ）

フリーモード（琴平10問）が主役。英語・漢字はオプション。 「英語もまぜる」=琴平5＋英語5、「漢字もまぜる」=琴平5＋漢字5、各「○○だけ」で単独10問。 難易度えらび・テーマえらびで絞り込み可。同じ日に同じ問題は出さない（localStorage）。

品質基準
選択肢の品質基準
  • 4つの選択肢は同カテゴリ・同粒度にする
  • 選択肢の文字数を4つとも揃える（最長と最短の比率は1.3倍以内。正解だけ長くしない）
  • ディストラクターは「よくある誤解」に基づき、もっともらしい具体性を持たせる
  • 「すべて正しい」「正しいものはない」は使わない
解説の方針（SEEED フレームワーク）
要素内容状態
S — Source信頼できる出典の明記運用中
E — Essence正答の核心的な理由運用中
E — Episode記憶に残るエピソード今後
E — Expansion関連知識への広がり今後
D — Discovery「へぇ」と思わせる豆知識今後

現状は主に Source＋Essence で構成。Episode 以降は段階的に拡充。

出典の信頼性 Tier
Tier例
Tier 1 高信頼公式サイト（konpira.or.jp, town.kotohira.kagawa.jp）、新聞社、学術資料、政府系（文化遺産オンライン等）
Tier 2 中信頼Wikipedia — 単独出典としては不十分。Tier 1 での裏取りが必要
Tier 3 参考個人ブログ、観光情報サイト — 補助的な参考のみ
残課題: Wikipedia 単独出典 167問の Tier 1 化（→ ロードマップ）。
既知の品質課題
  • konpie-bot ナレッジベース由来の問題は AI 生成のため事実確認が不十分な可能性
  • 例: 「こんぴらビール」は存在しない（正しくは「こんぴら麦酒」2008年製造終了、「呑象ブリューイング」2023年開業）
  • 内容矛盾の要確認: kotohira_450 / 466（車での参拝不可）が公式「お車参拝予約」と矛盾の可能性
  • 現地確認待ち: kotohira_645（金刀比羅宮の図書館が現在も開館しているか）
問題データのスキーマ

琴平クイズ

{ id, category, difficulty, question, choices[], answer,
  explanation, source, reviewed, enabled }

英単語クイズ

{ id, level, pattern, question, choices[], answer, explanation,
  word, pronunciation, search_url, translate_url, reviewed, enabled }

漢字読みクイズ

{ id, level, pattern, question, choices[], answer, explanation,
  word, reading, english, search_url, translate_url, reviewed, enabled }
# pattern: kanji_to_reading（漢字→読み）/ reading_to_kanji（読み→漢字）
# english: 英訳。複数はカンマ区切り（例: "offering, dedication"）
出題対象は enabled:true かつ reviewed:true のみ。 search_url / translate_url は作成時に word から生成して保存（毎回動的生成しない）。

設計方針・Bot 構成
設計方針（レビュー反映済み）
  • Repository Pattern / DI は不使用（Phase 1 では過剰設計＝YAGNI）
  • Bot の2問と Web の10問は独立（共有状態なし・意図的な割り切り）
  • JST 日付処理は sv-SE 方式で UTC/JST ズレを防止
  • JSON ロード失敗時はエラー画面（白画面にしない）
  • 重複フィルタは Set<string> で ID 比較
  • 正解はフロントに含む（Phase 1 は許容、Phase 2 でサーバー採点へ）
Discord Bot の投稿フォーマット
  • 🏛️ 琴平町クイズ 1問（Embed＋A/B/C/D ボタン）
  • 🔤 英単語クイズ 1問（Embed＋A/B/C/D ボタン）
  • 📝 残り8問は Web へ → 公開 URL（テキスト）

ボタン押下で ephemeral に正解/不正解＋解説。PersistentTeaserView で Bot 再起動後もボタンが動作。

問題データの正典は ~/hisho-bot/data/quiz/。kotohira-quiz-bot は環境変数 QUIZ_DATA_DIR で直接参照する。正典を kotohira-quiz 側へ移すかは技術的負債として保留中。
